# sentinel UI — нативный Win32-лоадер (C++)

Основной вариант приложения теперь находится в `main.cpp` и не требует .NET/WPF.
Это нативное Windows-приложение на C++17 с отрисовкой через GDI: выбор языка,
экран лицензии, hex-фон и визуальная последовательность сканирования сохранены.

## Сборка C++

```powershell
cmake -S . -B build
cmake --build build --config Release
./build/Release/DetectAcUI.exe
```

Либо из Developer Command Prompt for VS: `build-cpp.bat`.

Для Visual Studio также можно открыть каталог как CMake-проект.

Современный тёмный лоадер: чёрный + серый + красный акцент. Экран лицензии (EULA)
и экран «Forensic scan in progress». Чистый WPF, без сторонних библиотек.

## Запуск

Требуется Windows и .NET 8 SDK (либо Visual Studio 2022 с workload «.NET desktop development»).

```powershell
# из папки проекта
dotnet run

# или из родительской папки
dotnet run --project DetectAcUI
```

## Экран 0 — выбор языка

- При запуске — «Выберите язык / select language»: две карточки **Русский** и **English**.
- Hover: карточка приподнимается; выбор: красная рамка + свечение; «Продолжить · Continue»
  активируется после выбора (Enter тоже работает).
- После выбора весь UI локализуется: заголовки, бейдж, чекбокс, кнопки, все 17 разделов EULA,
  статусы и финал сканирования. Логи в hex-фоне остаются английскими (атмосфера).

## Экран 1 — License Agreement

- Кастомное окно без рамки: скругления 12px, мягкая тень, перетаскивание за шапку.
- Бренд `sentinel` (красная пульсирующая точка + версия), бейдж **REQUIRED**.
- Каскадное появление: шапка → карточка → подвал въезжают со сдвигом и фейдом.
- Текст лицензии листается **вручную** (автопрокрутки нет), тонкий серый скроллбар,
  снизу карточки — градиентное затухание как намёк на продолжение текста.
- Чекбокс «I have read and accept the terms»: галочка влетает с пружинкой (BackEase),
  кнопка **I Agree** плавно «зажигается» красным только после его отметки.
- Кнопки: анимированные hover (свечение, смена цвета) и нажатие (масштаб 0.965).
- Фон: живой «дамп памяти» — hex-строки с адресами, байтами и ASCII-колонкой,
  разбавленные строками логов sentinel; бесконечная прокрутка с рециклингом строк
  (верхняя строка уходит за край — снизу рождается новая, фон никогда не кончается)
  и случайные красные вспышки строк (эффект сканирования памяти).
  Непрозрачность слоя 3-6%, поверх — виньетка, чтобы текст и красный спиннер
  оставались главными акцентами.

## Экран 2 — Forensic scan

- Спиннер: вращающаяся красная дуга + лёгкое «дыхание» (SineEase).
- Статусы печатаются «печатной машинкой» с курсором-блоком, сменяются кроссфейдом.
- Переход между экранами: EULA уезжает влево с фейдом, скан поднимается снизу.
- Финал: спиннер сменяется красной галочкой с пружинкой, заголовок → «Scan complete».

## Общее

- Все движения — на смягчающих кривых (Circle/Cubic/Back ease), без резких стартов и стопов.
- Дрейф дампа обновляется покадрово (`CompositionTarget.Rendering`) с delta-time —
  идеально плавно на любой герцовке; красные вспышки строк — плавный кроссфейд цвета.
- Кнопки: подъём при наведении (translate), мягкое свечение, пружинистое нажатие.
- Переход экранов: EULA уезжает с ускорением, скан всплывает снизу с лёгким масштабом.
- Появление окна: fade-in + сдвиг вверх; закрытие — fade-out.
- `Enter` = I Agree (если чекбокс отмечен), `Esc` = Decline/Exit.
- После принятия EULA выполняется **реальное сканирование системы** (см. раздел ниже),
  по завершении кнопка «Открыть отчёт» открывает модальное окно с результатами.

## Реальное сканирование (после EULA)

Все 8 модулей работают с локальными артефактами Windows, ничего не отправляется в сеть.
Этапы выполняются последовательно (модули — в `Scanning/`), статус каждого этапа
печатается «печатной машинкой», счётчики находок накапливаются в журнале под статусом:

| Этап | Источник | Что извлекается |
|---|---|---|
| Steam-аккаунты | `config\loginusers.vdf` + реестр Steam | SteamID64, логин, отображаемое имя, последний вход, текущий автологин |
| Recent-файлы | `%APPDATA%\Microsoft\Windows\Recent\*.lnk` | имя, цель ярлыка (свой парсер .lnk + WScript COM), дата последнего открытия, поиск |
| ShellBags | `HKCU\…\BagMRU` | восстановленные пути Проводника; отсутствующие на диске — **удалённые**; записи корзины (0xbeef0008) с оригинальным путём и временем удаления |
| Prefetch | `C:\Windows\Prefetch\*.pf` | распаковка MAM/LZXPRESS-Huffman (ntdll), программа, число запусков, время последнего запуска; требует прав администратора |
| История браузеров | Chrome/Edge/Yandex/Brave/Opera + Firefox | визиты за 30 дней: копия History/places.sqlite читается собственным мини-SQLite-ридером (b-tree + overflow + WAL), поиск по URL/заголовку |
| PCI / DMA | реестр Enum\PCI + cfgmgr32 | все PCI-устройства, статус подключения/проблем, эвристика DMA-карт (Xilinx/Screamer/Captain/…) с красной подсветкой |
| Игровой софт | ключи Uninstall + процессы | Logitech G HUB/LGS, Razer Synapse, iCUE, SteelSeries, Bloody и др.; найденные папки макросов — кнопки «Открыть папку»; флаг «запущен сейчас» |
| USB-накопители | Enum\USBSTOR + setupapi.dev.log | устройство, серийник, последнее подключение/отключение (Properties 0066/0067), первая дата в системе |

## Окно отчёта

- Модальное окно в дизайне лаунчера: тёмный фон `#0B0B0E`, красный акцент `#FF3B4B`,
  Consolas, тонкие скроллбары, мягкие анимации, перетаскивание за шапку.
- Слева — разделы с цветными точками статуса и счётчиками, справа — таблица
  с подсветкой подозрительных строк, поиск (фильтрует все колонки) и примечания
  («нет доступа», усечение выборки и т.п.).
- Локализация RU/EN наследует язык, выбранный на первом экране.
- Открытие: кнопка **«Открыть отчёт»** на финале сканирования или `Enter`.
- **Полноэкранный режим:** кнопка в шапке / `F11` / двойной клик по шапке — окно
  разворачивается ровно по монитору (поверх панели задач, хук WM_GETMINMAXINFO);
  повторный `F11`/`Esc`/кнопка возвращает обычный размер. Окно также свободно
  масштабируется мышью в оконном режиме.

## Ограничения реального скана

- Prefetch читается только с правами администратора (иначе в отчёте пометка).
- Даты USB «подключён/отключён» берутся из `Properties\{83da6326…}\0066/0067`:
  ключи закрыты ACL даже для админа на части систем — тогда остаются даты из
  `setupapi.dev.log` (если журнал ротирован/очищен, дата не восстанавливается).
- История браузеров, открытая в момент скана, читается из копии базы + WAL;
  отдельные свежайшие визиты могут отсутствовать, если браузер не выгрузил журнал.
- ShellBags восстанавливают пути текущего пользователя Windows.

## Инструменты разработчика

- `tools/ScanHarness` — консольный прогон всех сканеров на живой машине
  (`dotnet run --project tools/ScanHarness [-- --report-ui]` — второй режим
  открывает окно отчёта без основного лаунчера). Исключён из сборки приложения
  (`Compile Remove="tools\**"` в csproj).
- `tools/e2e.ps1` — автоматизированный UI-тест полного сценария (язык → EULA →

- `global.json` закрепляет SDK 8 (сборка выполнялась SDK 8.0.426).

## Система доступа: временный одноразовый ключ модератора

Чекер не запускается без действующего ключа. Ключ выдаёт модератор через
веб-панель (`panel/`), пользователь вставляет его при запуске лоадера.

### Схема работы

```
модератор                     сервер (sentinel-panel)              чекер (лоадер)
   │  открывает панель,             │                                  │
   │  вводит код доступа      POST /login (cookie)                     │
   │  выбирает срок (часы)          │                                  │
   │  ────────────────────────►  создаёт ключ SENT-XXXXX-XXXXX-XXXXX   │
   │  ◄──────── посылает ключ пользователю                             │
   |                                                                  │
   |                              ◄──  POST /api/activate {key, machineId}
   |                    ключ принят ровно один раз,                 │
   |                    привязан к отпечатку ПК,                ──►  экран выбора языка
   |                    выдан session-ticket на N часов             (и далее EULA → скан)
   |                                                                  │
   |                              ◄──  POST /api/validate {ticket, machineId}
   |              каждый запуск: сессия проверяется на сервере;    │
   |              истёкшая/отозванная запись удаляется —           │
   |              без нового ключа доступ невозможен
```

### Панель модератора (`panel/`, ASP.NET Core, net8.0)

```powershell
# задать код доступа и запустить
$env:SENTINEL_PANEL_CODE = "<секретный код>"   # либо Panel:AdminCode в appsettings.json
dotnet run --project panel                     # http://0.0.0.0:5177
```

В браузере — страница `/`: вход по коду, поле «срок действия (часы)», кнопка выпуска
ключей, таблица всех ключей со статусами `unused / active / expired / revoked` и отзыв.
Ключи хранятся в `panel/bin/.../data/keys.json` (состояние — только на сервере).

API панели:

| Эндпоинт | Кто вызывает | Назначение |
|---|---|---|
| `POST /api/activate { key, machineId }` | чекер | одноразовая активация → `{ ok, reason, ticket, expiresAt }` |
| `POST /api/validate { ticket, machineId }` | чекер | проверка сохранённой сессии при каждом запуске |
| `POST /admin/keys { hours, count }` | панель | выпустить ключи на N часов |
| `GET /admin/keys` · `POST /admin/keys/revoke { id }` | панель | список / отзыв |

### Чекер (C++ `main.cpp` + `Licensing/license_core.h`; WPF — `Licensing/*.cs`)

1. При старте читается `%LOCALAPPDATA%\sentinel\session.dat` (токен + срок + отпечаток ПК).
2. Есть сессия → `POST /api/validate`; сервер принял → сразу выбор языка.
3. Нет сессии / сервер отказал → экран **«Введите ключ доступа»** (вручную или Ctrl+V).
4. **Активировать** → `POST /api/activate`. Успех → токен сохраняется локально,
   открывается выбор языка. Отказ («ключ не валиден», уже использован, истёк,
   отозван, чужой ПК) → сообщение о причине и **чекер закрывается**.
5. Адрес панели — `sentinel.config.json` рядом с exe (`ServerUrl`) или переменная
   окружения `SENTINEL_SERVER_URL`; без адреса доступ запрещён (`NO_SERVER`).

### Гарантии

- **Единоразовость**: после первой активации ключ навсегда помечен `UsedAt`;
  повторная попытка → `KEY_USED` → закрытие чекера.
- **Привязка к ПК**: `machineId` = SHA-256 от `имя ПК\пользователь|MachineGuid`;
  чужая машина → `MACHINE_MISMATCH`. Скопированный `session.dat` не принимается.
- **Ограниченный срок**: сессия живёт ровно `DurationHours`; фоновый таймер панели
  каждые 60 с **удаляет** истёкшие записи — возобновить доступ можно только новым ключом.
- **Отзыв модератором**: `revoked` мгновенно ломает и ключ, и активную сессию.
- Без сети чекер не работает (`NETWORK`) — офлайн-обход через подмену файла невозможен,
  т.к. решение всегда принимает сервер.

### Отладка без GUI

`tools/liccli.exe activate <ключ> | check | clear` — консольный клиент того же API
(исходник `tools/liccli.cpp`). Автотест жизненного цикла ключей: `tools/test-panel.ps1`.
